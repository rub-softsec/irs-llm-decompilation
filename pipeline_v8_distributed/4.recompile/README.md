# Recompilation Pipeline

This directory contains the fourth stage of the pipeline, which attempts to recompile the C code generated by the LLMs into object files.

## Purpose

To verify the syntactic correctness and compilability of the decompiled code, we attempt to compile each generated C file using GCC. We inject the original function dependencies (headers, type definitions) to ensure a fair compilation attempt.

## Workflow

### 1. Recompilation (`main.py`)

Execute the main script to start the recompilation process.

```bash
python3 main.py
```

*   **Input**: 
    *   `input/`: Directory containing the decompiled C files (usually symlinked or copied from `../3.queries_LLMs/output/`).
    *   `json/selected.jsonl`: Metadata file containing dependencies (`deps`) and function headers (`func_head`) for each function ID.
*   **Action**: 
    1.  Loads metadata to retrieve dependencies for each function.
    2.  Scans `input/` for .c files.
    3.  For each file, combines the decompiled code with its dependencies.
    4.  Attempts to compile using `gcc -c`.
*   **Output**: 
    *   `output/<path>/<filename>.o`: Successfully compiled object files.
    *   `output/error/<path>/<filename>.error`: Detailed error logs for failed compilations.
    *   `error.txt`: Summary log of all errors.

## Generated Artifacts

*   **Object Files**: Valid object files for functions that successfully recompiled.
*   **Error Logs**: Diagnostics for compilation failures, useful for error taxonomy analysis.
